## Schema Definition

### Table Structure

**Table Name**: `locations`

**Fields**:

- `id` (text, primary key) - Unique identifier for each location
- `name` (text, not null) - Location name in Romanian (e.g., "București", "Cluj-Napoca")
- `type` (location_type enum, not null) - Type: "county" | "city" | "sector"
- `parent_id` (text, nullable) - Self-referential foreign key to parent location
- `code` (text, nullable) - County code (e.g., "B", "CJ", "TM")
- `is_active` (boolean, default: true) - Soft delete flag
- `created_at` (timestamp, default: now()) - Creation timestamp
- `updated_at` (timestamp, default: now()) - Update timestamp

### Enum Type

**Enum Name**: `location_type`

**Values**:

- `county` - Județ (41 counties + Bucharest)
- `city` - Municipiu or oraș (cities)
- `sector` - Sector (Bucharest sectors 1-6)

## Indexes

### Performance Indexes

1. **`idx_locations_type`** - Index on `type` field
   - Used for filtering by location type (county/city/sector)

2. **`idx_locations_parent_id`** - Index on `parent_id` field
   - Used for hierarchical queries (get all cities in a county)

3. **`idx_locations_code`** - Index on `code` field
   - Used for filtering by county code

4. **`idx_locations_is_active`** - Index on `is_active` field
   - Used for filtering active/inactive locations

### Unique Indexes

1. **`idx_locations_name_type_parent_unique`** - Composite unique index on `(name, type, parent_id)`
   - Prevents duplicate cities/sectors with the same name and parent
   - Note: For counties (parent_id IS NULL), this doesn't work as expected due to NULL handling

2. **`idx_locations_county_name_unique`** - Partial unique index on `(name, type)` WHERE `type = 'county' AND parent_id IS NULL`
   - Ensures county name uniqueness
   - Only applies to counties (where parent_id IS NULL)

### Composite Indexes

1. **`idx_locations_type_parent`** - Composite index on `(type, parent_id)`
   - Optimizes queries like "get all cities in a county"

2. **`idx_locations_code_type`** - Composite index on `(code, type)`
   - Optimizes queries filtering by county code and type

---

## Constraints

### Foreign Key Constraints

**Self-Referential Foreign Key**:

- `parent_id` → `locations.id`
- **ON DELETE**: SET NULL (if parent is deleted, child's parent_id becomes NULL)
- **ON UPDATE**: CASCADE (if parent id changes, child's parent_id updates)

This allows hierarchical relationships:

- Counties: `parent_id = NULL`
- Cities: `parent_id = county.id`
- Sectors: `parent_id = city.id` (Bucharest city)

## Technical Notes

### Self-Referential Foreign Key

The self-referential foreign key was added manually in the migration file because:

- Drizzle ORM doesn't automatically generate self-referential foreign keys in schema definition
- The constraint ensures referential integrity for hierarchical relationships

### Partial Unique Index for Counties

The partial unique index was added because:

- Standard unique index on `(name, type, parent_id)` doesn't work for counties (parent_id IS NULL)
- PostgreSQL treats NULL values as distinct in unique constraints
- Partial index ensures county name uniqueness while allowing the standard unique index for cities/sectors

### Index Strategy

The index strategy optimizes for common query patterns:

- Filtering by type (county/city/sector)
- Getting all children of a parent (cities in county, sectors in city)
- Filtering by county code
- Ensuring data integrity (unique constraints)
